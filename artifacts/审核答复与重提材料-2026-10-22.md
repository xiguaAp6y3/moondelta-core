## 2. 目标协议与必需行为范围（审核要求第 1 点）

**目标协议**：reader v1 / writer v2 完整实现。必需行为闭集（ROADMAP §2，逐项有测试）：

- 协议协商：`minReaderVersion != 1` 拒绝并说明；`readerFeatures`/`writerFeatures` 解析；`add.deletionVector` 拒绝；
- 日志：20 位文件名严格校验；连续回放 / 时间旅行；**checkpoint 恢复**（单文件经典 checkpoint，兼容 Spark 与 delta-rs 两种可空性标注；多部分 checkpoint 显式拒绝）；
- actions：protocol/metaData/add/remove/commitInfo 完整语义、txn 识别、cdc/domainMetadata 显式忽略并提示、未知 action 结构化拒绝；
- schema：全部 primitive（boolean/byte/short/int/long/float/double/string/binary/date/timestamp）+ **嵌套 struct/array/map 读写**（NULL、空集合、null 元素/子字段）；
- Parquet：SNAPPY/UNCOMPRESSED；`add.path` percent-decoding；数据文件缺失结构化错误（含文件名）；
- 统计：flat min/max 剪枝；嵌套字段放弃剪枝保证正确读取；stats 损坏显式报错；
- 写路径：create 防重、append 校验列名/类型/NOT NULL、数据文件与 commit 均 put-if-absent、writer>2 拒绝；
- CLI：错误到 stderr、非 0 退出码、参数校验。

**显式例外（申报同步列出，拒绝均带原因）**：decimal、uuid、ZSTD/GZIP/BROTLI/LZ4、对象存储、reader≥2 特性、多部分 checkpoint、分区 append、MERGE/UPDATE/DELETE、并发仲裁。

## 3. 同一协议下的对照案例（审核要求第 2 点）

同一配置：`minReaderVersion=1, minWriterVersion=2`、按版本编号 JSON log、SNAPPY Parquet。外部引擎：delta-rs 1.6.6 与 DuckDB（delta 扩展）。

- **案例 A（flat，`id long NOT NULL / name string / active boolean`）**：双向通过。外部写 → 本项目读、本项目写 → 外部读，49 PASS / 0 FAIL / 2 项已记录差异（`artifacts/interop-flat/`，2026-10-22 复验 17/17）。
- **案例 B（nested，`profile struct / tags array / attrs map`，5 行含 `profile=NULL`、空集合、null 元素/子字段）**：双向通过。
  - 外部写（engine-written 等 5 个 fixture）→ 本项目读取：与 delta-rs oracle 逐值一致（`artifacts/acceptance/m2/`）；
  - 本项目写（`artifacts/interop-nested/moondelta-nested-written/`，由 `src/examples/write_nested` 产出）→ delta-rs 与 DuckDB 回读：10/10 检查逐行逐字段一致（`artifacts/acceptance/m4/external-readback.json`）。
- **checkpoint 案例**：`checkpoint-truncated`（JSON 截断 + checkpoint v10）恢复为 v10/100 文件（修复前静默读 v9/90）；`checkpoint-only-nested` 从 checkpoint 恢复后嵌套值与 oracle 一致。

终态验收：[artifacts/acceptance/full-compat-final-2026-10-22.md](acceptance/full-compat-final-2026-10-22.md)——**0 FAIL，七项门槛 7/7**。
