## 项目简介

MoonBit 已有 Parquet 编解码（`mizchi/parquet`）、Arrow IPC、DataFrame（MoonFrame）、对 CSV/Parquet 跑 SQL 的引擎（moonlake）、Iceberg 只读（moonice），但**没有"带事务日志的表"**：没有版本、快照、时间旅行，也没有把一批 Parquet 文件原子提交成新版本的机制。结果是文件能读、表还得自己拼——回滚、按版本审计、增量入湖只能手写 JSON 解析加目录扫描，或者把整段逻辑绕去 Python/Spark。

moondelta-core 补这一层：打开磁盘上的 Delta 表目录，回放 `_delta_log`，给出指定版本的文件清单，按分区与 min/max 统计剪枝，读取数据文件，并在受支持的列类型上 append 提交新版本。

## 通用性说明

- 与具体业务无关：凡是需要"版本化表"的场景都能直接复用——ETL 写出、外部表校验与迁移、CI 数据契约审计、增量入湖；
- 格式与生态一致：读写 Delta protocol reader v1 / writer v2、version 0 起连续 JSON 日志、flat schema、UNCOMPRESSED/SNAPPY 压缩与本地文件系统范围内的目录；flat 表已完成与 delta-rs 1.6.6、DuckDB 1.5.6 的双向目录级对拍（D2：49 PASS / 0 FAIL / 2 项已记录差异，见 `artifacts/interop-flat/README.md`），Spark / Databricks 未在本环境验证；闭集之外当前并非“明确拒绝”：删除向量被静默忽略并读全量、截断日志 + checkpoint 被当作旧版本读、reader v2/v3 与未知必需 feature 不被拒绝（见 `artifacts/protocol-audit.md` §5）；nested 读写的第 3 节七项门槛仅完成 1/7（仅证据门槛 6，不构成 nested 兼容，见 `artifacts/interop-nested/README.md`），需完成 nested 读写、checkpoint 恢复与至少两种外部引擎对拍等门槛后再扩大承诺；
- 不绑定运行时：库只处理目录与文件，不依赖 JVM/Rust 运行时，native 目标可用，后续可扩 wasm/js；当前存储只实现本地文件系统，对象存储未实现；
- 边界显式：对已识别的闭集边界（嵌套 schema、ZSTD/GZIP/BROTLI/LZ4、不在支持列表的写入类型）返回结构化错误；但闭集之外尚未全部拒绝——删除向量与未知 feature 未检测、append 不校验列名/类型/NOT NULL、stats 非 string 时行数显示 0、CLI 错误退出码恒 0（`artifacts/protocol-audit.md` §5 列出 15 条声明不一致），这些是待修复的静默/未检测项，不能视为“不静默降级”——数据基础设施宁可拒绝，不可返回错数据。

## 预期使用场景

1. **MoonBit ETL 写出、外部引擎读取**：输入是清洗后的记录（Int64/String 列），操作 `create_table` + `append_rows`（写 Parquet 数据文件并提交新版本），输出 Delta protocol reader v1 / writer v2 目录；D2 已用 delta-rs 1.6.6 与 DuckDB 1.5.6 回读本项目写出的 flat 表（schema/行数/逐列值一致，见 `artifacts/interop-flat/README.md`），Spark / Databricks 的 `spark.read.format("delta")` 读取尚未验证；本场景仅覆盖闭集内 flat 表，闭集外表的已知缺口见 `artifacts/protocol-audit.md` §5；MoonBit 侧不需要装 Spark。
2. **外部表校验与迁移**：输入 delta-rs 或 Databricks 产出的 flat 表（例如 COVID-19_NYT；本仓库 fixture 只含该表 1 个 157,865 行 6 列的数据文件与 version 0 日志，对比两个版本需另备日志与数据文件齐全的表），操作 `snapshot_at(v)` + 扫描 + 读取，对比文件清单、行数与值，输出校验报告或 CSV——迁移前确认数据没缺、历史对得上；注意当前对 reader≥2、含删除向量或 column mapping 的表未做检测（见 `artifacts/protocol-audit.md` §5）。
3. **CI 数据契约审计**：输入仓库里随代码提交的小型 Delta 表和两个版本号，操作按版本回放 + 分区/min-max 剪枝，输出"这次提交改了 N 个数据文件、影响 M 行、落在 dt=… 分区"的 Markdown artifact；纯读路径，不需要写权限。

## 拟实现的核心功能

- **事务日志解析与回放**：`_delta_log` 逐行 action（protocol / metaData / add / remove / commitInfo），版本发现与排序、`_last_checkpoint` 识别；
- **快照与时间旅行**：按版本顺序叠加 add/remove，同路径 add→remove→add 正确收敛；`snapshot_at(v)`、`history()`；
- **扫描规划**：分区等值过滤 + 文件级 min/max 统计剪枝，返回文件清单、跳过数、命中行数与字节数；
- **读取**：flat schema + UNCOMPRESSED/SNAPPY 数据文件；分区列按 `partitionValues` 补齐；
- **写入**：`create_table` + `append_rows`，写 Parquet 数据文件、提交新的 JSON 版本，统计信息（numRecords 与数值列 min/max；无 nullCount、无字符串/布尔 min/max）随日志写入；
- **CLI 与工程化**：`delta inspect | history | scan | read | create`、可运行示例、14 个单元测试（含负向）、CI（check/build/test）、mooncakes.io 发布。

## 移植或参考说明

- **参考规范**：Delta Lake 协议规范 https://github.com/delta-io/delta （Apache-2.0），仅按规范实现，未复制 delta-rs / Spark 代码；测试数据来自 delta-rs 与 apache/parquet-testing（均 Apache-2.0），逐项来源与哈希见 `fixtures/README.md` 与 `THIRD_PARTY_NOTICES.md`；
- **实现方式**：从零手写约 2,575 行 MoonBit（按文件全行统计：核心库 1,508、CLI 383、测试 570、示例 114，其中含 D2 新增的 69 行互操作写入示例）；唯一运行时依赖为 `moonbitlang/x@0.5.5`；Parquet 编解码 vendored `mizchi/parquet@0.2.2`（Apache-2.0，删掉两个 DuckDB 演示子包；reader 未改，writer 扩展 BOOLEAN/DOUBLE 写入，NOTICE 记录来源与修改）；
- **实现路径**：不包 delta-rs/Spark（MoonBit 没有 JVM/Rust 绑定，且只是壳），也不自造列存（重复造轮子）；只做协议层，复用 Parquet 与 core JSON，sans-IO 核心 + 文件系统薄封装，日志回放可用真实 fixture 离线对拍；
- **边界与简化**：读取只承诺 Delta protocol reader v1 的表、写出 writer v2 的表，且日志必须从 version 0 起连续；高于 reader v1 的 protocol（v2/v3）、`readerFeatures`/`writerFeatures` 与未知必需 feature 当前不校验、不拒绝；不实现嵌套 schema（struct/list/map）与 ZSTD/GZIP/BROTLI/LZ4，仅支持 UNCOMPRESSED/SNAPPY 压缩与本地文件系统；不解析 checkpoint parquet：checkpoint-only 表返回结构化 NotFound（消息为“has no log entries”），而日志被截断但存在 checkpoint 的表当前会当作旧版本读取（未检测，已知缺口）；删除向量（`deletionVector`）、column mapping、CDF 当前未检测（可能读全量或报误导错误）；写入支持 Int32/Int64/String/Binary/Boolean/Double，append 只校验列数/行长、不校验列名/类型/NOT NULL，写出列恒为 Parquet Optional；不写分区表；不做对象存储、MERGE/UPDATE/DELETE、并发写冲突仲裁、SQL/DataFrame 层。
