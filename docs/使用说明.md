# moondelta-core 使用说明（0.4.0）

本文面向使用者：如何安装/构建、CLI 子命令、核心库 API（含事务查询与恢复、嵌套读写）、错误语义与能力边界。registry 最新发布仍为 0.3.1，本文描述的是本地 0.4.0 工作区能力。协议口径的正式定义见[协议兼容性与互操作范围.md](协议兼容性与互操作范围.md)；测试方法见[测试说明.md](测试说明.md)。

## 1. 安装与构建

```bash
# 从 mooncakes.io 安装当前发布版本 0.3.1（本地 0.4.0 尚未发布）
moon add xiguaAp6y3/moondelta-core

# 或从源码构建（native 目标）
moon check --target native   # 0 errors
moon test  --target native   # 56/56
moon build --target native
```

要求：2026-10 之后的 MoonBit 工具链（moon / moonc）。运行时依赖仅 `moonbitlang/x@0.5.5`；Parquet 编解码 vendored 于 `src/vendor/parquet`（来源与修改见其 `NOTICE.md`）。

## 2. CLI

二进制位于 `src/cmd/delta`（源码构建后为 `_build/native/debug/build/cmd/delta/delta.exe`）。约定：**正常输出走 stdout，错误走 stderr；成功退出码 0，任何失败非 0**。

```bash
D=_build/native/debug/build/cmd/delta/delta.exe

# 查看：版本、协议、schema、文件/行数/字节、checkpoint 提示、被忽略 action 提示
$D inspect fixtures/delta/table_a
# table            : fixtures/delta/table_a
# current version  : 12  (log versions: 13)
# files            : 120  rows: 120  bytes: 54232
# protocol         : reader=1 writer=1
# ...
# note             : checkpoint present; truncated / checkpoint-only tables are recovered
#                    from the latest single-file checkpoint

# 版本历史
$D history fixtures/delta/table_a

# 扫描规划（分区等值过滤 + min/max 统计剪枝；不读数据文件）
$D scan fixtures/delta/table_a --where "id>=60"
# total files: 120  selected: 60  skipped stats: 60  matched rows: 60
$D scan <table> --partition dt=2026-01-01

# 读取数据（默认 limit 10）
$D read fixtures/delta/covid --limit 5
$D read fixtures/delta/byte-short        # byte/short 列
$D read artifacts/interop-nested/engine-written  # 嵌套列以 JSON 风格渲染
$D read artifacts/interop-nested/moondelta-nested-written   # 嵌套表（本项目写出）

# 建表（schema 传 JSON 字符串或 .json 文件路径；重复建表会被拒绝）
$D create <table-root> '{"type":"struct","fields":[{"name":"id","type":"long","nullable":true,"metadata":{}}]}'

# 事务恢复：默认 dry-run，只列出候选；--apply 仅对显式受管表生效
$D recover <table-root>
$D recover <table-root> --apply
$D manage  <table-root>            # 显式标记“全部 writer 遵守 moondelta 维护锁”
$D manage  <table-root> --disable
$D query   <table-root> <txn-id>   # committed / committed-unconfirmed / conflict / not-committed / unresolved

# 版本
$D version
```

参数错误（未知 flag、缺值、非法 `--where`）与所有运行时错误同样走 stderr 并以退出码 1 结束。

## 3. 核心库 API

### 3.1 读取：打开 → 快照 → 读取

```moonbit
let table = @delta.DeltaTable::open("path/to/table")          // 无 _delta_log 报 NotFound
let snapshot = table.snapshot()                                // 最新版本
let old      = table.snapshot_at(3)                            // 时间旅行
let history  = table.history()                                 // commitInfo 列表
let current  = table.current_version()                         // max(JSON 最新, checkpoint 最新)

let result = @delta.read_snapshot("path/to/table", snapshot, Some(100))  // limit
// result.columns : Array[ReadColumn]（含分区列补齐）
// result.row_count / files_read
```

单元格为 `Cell` 枚举：`CellI32/CellI64/CellF32/CellF64/CellBool/CellStr/CellBin/CellTs/CellNull`，嵌套值 `CellStruct(Array[(String, Cell)])` / `CellList(Array[Cell])` / `CellMap(Array[(Cell, Cell)])`；`@delta.cell_to_display` 输出 JSON 风格文本。

### 3.2 扫描规划（不读数据文件）

```moonbit
let report = @delta.scan(snapshot, {
  partitions: [("dt", "2026-01-01")],            // 分区等值过滤
  predicate: Some({ column: "id", op: GeV, value: 60.0 }),  // 单列 min/max 剪枝
})
// report.files / skipped_partition / skipped_stats / matched_rows / matched_bytes
```

### 3.3 写入：建表 + 追加

```moonbit
let schema = "{\"type\":\"struct\",\"fields\":[{\"name\":\"id\",\"type\":\"long\",\"nullable\":true,\"metadata\":{}}]}"
let (v0, create_txn) = @delta.create_table_with_txn(root, schema, [])  // 已存在则报错；写出 protocol v1/v2

let columns : Array[@delta.ReadColumn] = [
  { name: "id", type_: @delta.Int64Type, cells: [@delta.CellI64(1L), @delta.CellNull] },
]
let (version, txn_id) = @delta.append_rows_with_txn(root, columns, timestamp) // 返回新版本号与 txn ID
```

写入语义：`append_rows` 支持 11 种基础类型及嵌套叶，校验列数/列名/类型/NOT NULL；每次写入先持久发布 intent（目标版本、临时/正式路径、长度与 SHA-256），再按 intent 固定的临时名排他发布数据与 JSON commit；数据文件与 commit 文件均为 put-if-absent（目标已存在即失败）；`writer protocol > 2` 或非空 `writerFeatures` 的表拒绝 append。完整全类型示例见 `src/examples/write_all_types`。

### 3.4 事务查询与保守恢复（S2/S3）

```moonbit
// 只读：不删除、不回滚、不重放
let status = @delta.query_transaction(root, txn_id)
println(@delta.txn_state_name(status.state))   // committed / committed-unconfirmed / conflict / not-committed / unresolved；Windows 上没有目录项同步原语，匹配后为 committed-unconfirmed
println(status.phase + " " + status.detail)

// 默认 dry-run；只有 @delta.set_managed_table(root, true) 之后的受管表才允许 apply
let report = @delta.recover_table(root, true)
for entry in report.entries {
  println(entry.action + " " + entry.path + " (" + entry.reason + ")")
}
let applied = @delta.recover_table(root, false)  // 未受管 → blocked，仅预览
@delta.set_managed_table(root, true)             // 确认全部 writer 都遵守维护锁后启用
let cleaned = @delta.recover_table(root, false)  // 真正删除候选
```

恢复只删除 intent 精确列出的临时名，以及“日志自版本 0 起连续可解析 + 不受任何可见历史/checkpoint 引用 + 路径/长度/摘要吻合”的正式 Parquet；未知文件、旧命名临时文件、软链接与越界路径一律保留并报告。提交成功后的尾部清理失败只会保留 intent 供下次恢复，不会把已确认提交改报为失败。

### 3.5 嵌套写入

传入与表 schema 同构的嵌套 `Cell`（结构校验失败会报错）。完整可运行示例见 `src/examples/write_nested`：

```bash
moon run --target native src/examples/write_nested -- <table-root>
```

要点：嵌套字段的 `type_` 需构造为 `@delta.NestedType(kind=..., fields=...)`（array 的合成字段名为 `element`，map 为 `key`/`value`）；`CellNull`、空 `CellList([])`/`CellMap([])`、含 null 元素的列表均为合法输入。嵌套字段不写 min/max 统计（放弃剪枝、保证正确读取）。

## 4. 错误语义

核心层错误类型 `DeltaError`（`IoError / AlreadyExists / CommitConflict / PublishOutcomeUnknown / CommitOutcomeUnknown / ParseError / Unsupported / NotFound`），`describe_error` 输出带前缀的可读文本；CLI 层统一"stderr + 非 0 退出码"。典型行为：

| 场景 | 行为 |
|---|---|
| reader ≥ 2 / writer > 2 / 未知 features / deletionVector | `unsupported`，错误含版本或特性名与原因 |
| 日志缺版本（缺口） | `not found: log version N is missing (log gap ...)` |
| 截断日志 / checkpoint-only | 从最新单文件 checkpoint 恢复；无法恢复时报 `predates the earliest available checkpoint` |
| 非 20 位日志文件名 | `parse error: invalid _delta_log file name ...` |
| 未知 action | `unsupported: unknown action '<名>'`（cdc/domainMetadata 例外：显式忽略 + inspect 提示） |
| create 已存在的表 / append 列名类型不符 / commit 位置被占 | 相应结构化错误，均不覆盖既有数据 |
| 数据已可见但目录同步失败 | `publish outcome unknown: txn <id> target version <v> phase <p> ...`（不发布 JSON，可安全重试前先恢复） |
| 正式 commit 已可见但持久性未确认 | `commit outcome unknown: txn <id> target version <v> phase <p> ...`（禁止盲目重放，先 `query` 核对） |

## 5. 能力边界（显式例外）

不支持并结构化拒绝：decimal、uuid、`timestamp_ntz`、timestamp millis/nanos；ZSTD/GZIP/BROTLI/LZ4 压缩；reader ≥ 2 / writer > 2 的全部特性（column mapping、deletion vectors、v2 checkpoint）；多部分 checkpoint；checkpoint 缺失 protocol/metaData 或出现真实未知 action；非空 `writerFeatures`；分区表 append；MERGE/UPDATE/DELETE；对象存储。并发写通过固定维护锁 + put-if-absent 返回 `CommitConflict`，但这不是通用事务仲裁；S5 掉电持久性已在指定 CI 配置下通过 100 轮模型化切断（证据见 `artifacts/acceptance/powerloss/ci-2026-11-12/`），该结论不外推到其它 host 与文件系统；Windows 仅声明进程崩溃一致性。flat 与 nested 叶均校验 Delta/Parquet 类型一致性。当前能力矩阵见 [README](../README.md) 与 [项目路线说明](项目路线说明.md)。
